# presentation-maker

Генератор презентаций по PPTX-шаблону. На входе — слайды-образцы, задача и материалы проекта: файлы, архив или Git-репозиторий. На выходе — `.pptx` и текст выступления в `.md`. В веб-интерфейсе можно следить за генерацией и открыть режим спикера.

Шаблон сначала проходит анализ: сервис извлекает оформление, текстовые поля и их вместимость. При генерации LLM составляет план и тексты, а движок собирает презентацию на основе слайдов шаблона. Дообучения модели здесь нет.

## Локальный запуск

Нужны Node.js 22.12+, pnpm 12.3.4, Docker с Compose v2 и доступ к OpenAI-совместимому API.

```bash
pnpm install
pnpm infra:up
cp -n apps/api/.env.example apps/api/.env
```

В `apps/api/.env` заполните `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`. Затем:

```bash
pnpm db:migrate
pnpm dev
```

- Интерфейс: [localhost:5173](http://localhost:5173).
- API и Swagger: [localhost:3000/docs](http://localhost:3000/docs).
- PostgreSQL: `localhost:5433`; Redis: `localhost:6380`.

Для PNG-превью нужны LibreOffice и Poppler. Без них презентация собирается, но в интерфейсе используется текстовое превью.

Подробности: [установка, настройки, Docker и разбор ошибок](docs/getting-started.md).

## Первая презентация

1. Откройте «Шаблоны», загрузите `.pptx` со слайдами-образцами и дождитесь статуса «Готов».
2. В «Новой презентации» выберите шаблон, опишите задачу и аудиторию, укажите длительность выступления и добавьте материалы.
3. Запустите генерацию. После завершения откройте слайды, проверьте факты и скачайте `.pptx` или текст выступления.

Полезный бриф содержит цель и ограничения. Например: «За 7 минут объяснить жюри, какую проблему решает проект, показать устройство сервиса и сценарий демо. Не добавлять метрики, которых нет в материалах».

Воркер по умолчанию обрабатывает три генерации одновременно. Бюджет одной задачи — 5 минут; он задан константой `GENERATION_TIME_BUDGET_MS` в [packages/shared/src/constants.ts](packages/shared/src/constants.ts). Это ограничение выполнения, а не гарантия успешной сборки за указанное время: результат зависит от шаблона, модели и нагрузки.

## CLI

API должен быть запущен. Загрузите шаблон:

```bash
pnpm cli health
pnpm cli templates upload ./brand.pptx --name "Бренд" --wait
pnpm cli templates list
```

Подставьте ID готового шаблона в команду:

```bash
pnpm cli presentations create \
  -t <template-id> \
  -b "Финал хакатона: проблема, решение, архитектура, демо" \
  -s ./docs -s https://github.com/org/repo \
  -d 7 -o final.pptx
```

`-s` можно повторять; принимаются папки, `.zip`, файлы и Git-ссылки. `-d` задаёт длительность выступления в минутах. `-o` дожидается результата и сохраняет рядом `final.pptx` и `final.md`. Бриф из файла передаётся через `-f ./brief.md` вместо `-b`.

У команд есть `--help`, `--json` и `--api-url`. Адрес сервера также можно задать через `PM_API_URL`.

Для замера трёх параллельных генераций на своей модели и шаблоне:

```bash
pnpm cli bench -t <template-id> -b "Финал хакатона" -s ./docs -d 7
```

## Устройство проекта

| Каталог           | Назначение                                                              |
| ----------------- | ----------------------------------------------------------------------- |
| `apps/api`        | NestJS: HTTP API, Prisma, работа с файлами и обработчики очередей       |
| `apps/ml`         | Разбор OOXML, анализ шаблона, вызовы LLM, подгонка текста и сборка PPTX |
| `apps/web`        | React и Vite: шаблоны, генерация, просмотр и режим спикера              |
| `apps/cli`        | Клиент API на oclif, загрузка материалов и бенчмарк                     |
| `packages/shared` | Zod-схемы, типы, константы и клиент API                                 |
| `infra/dev`       | PostgreSQL и Redis для локальной разработки                             |
| `infra/prod`      | Docker-образы и Compose для API, воркера и интерфейса                   |

API хранит метаданные в PostgreSQL и ставит задания в BullMQ через Redis. Очередь `template-analysis` обрабатывает шаблоны, `presentation-generation` — презентации. Исходные файлы, результаты и превью лежат в `STORAGE_DIR`; база хранит ссылки на них.

При генерации движок готовит выжимку материалов, запрашивает план, выбирает макеты и заполняет их текстом. Ответы LLM проверяются Zod-схемами. Нативный рендер использует слайды исходного шаблона и записывает текст выступления в заметки спикера. PNG-превью строятся через LibreOffice и Poppler.

`APP_ROLE=all` запускает HTTP и воркеры в одном процессе. В Docker они разделены: `APP_ROLE=api` принимает запросы, `APP_ROLE=worker` выполняет задания. Это позволяет менять число воркеров отдельно от API.

Контракты HTTP доступны в Swagger. Загрузка шаблона — `POST /templates`, создание презентации — `POST /presentations`, проверка статуса — `GET /presentations/:id`. Готовые файлы доступны по `/presentations/:id/file` и `/presentations/:id/script`.

## Разработка

```bash
pnpm typecheck
pnpm test
pnpm build
```

`pnpm dev` собирает общие библиотеки и запускает API, веб-интерфейс и библиотеки в watch-режиме. `pnpm db:studio` открывает Prisma Studio. `pnpm format` форматирует весь репозиторий.

## Развёртывание

```bash
cp -n infra/prod/.env.example infra/prod/.env
```

Задайте `POSTGRES_PASSWORD`, параметры `LLM_*` и `WEB_PORT` в `infra/prod/.env`. Например, `WEB_PORT=8080` откроет интерфейс на [localhost:8080](http://localhost:8080).

```bash
docker compose -f infra/prod/docker-compose.yml --env-file infra/prod/.env up -d --build
```

Compose применяет миграции, запускает API и воркер, затем nginx с веб-интерфейсом. Nginx направляет запросы `/api` в API. API и воркер используют общий том `storage`, поэтому эта конфигурация рассчитана на одну машину.

## Ограничения

Для первого запуска используйте шаблон со слайдами-образцами: именно они служат основой для сборки. Загрузка файла сама по себе не означает, что все его элементы подойдут для генерации.

PNG-превью зависят от LibreOffice и установленных шрифтов; отображение в PowerPoint может отличаться. Перед выступлением проверьте скачанный файл на машине, с которой будете показывать слайды.

Текст и заметки создаёт LLM. Числа, имена и утверждения о проекте нужно сверить с исходными материалами.
