# presentation-maker

Сервис генерации презентаций по брендовому шаблону.

1. **Подготовка (время не ограничено).** Загружаем шаблон или контент-пакет компании. Он уходит в очередь, воркер «обучается» на нём: выделяет токены, шрифты, лейауты, тон. После этого шаблон переходит в `READY`.
2. **Генерация (бюджет 5 минут).** По готовому шаблону и задаче (репозиторий, документация, история команды, лимит выступления) генерируются слайды и текст спикера к каждому. Три презентации идут параллельно и все должны уложиться в 5 минут.

## Структура

```
apps/
  api/        Nest.js 12 (express): шаблоны, презентации, очереди BullMQ, Prisma, swagger
  web/        React + Vite: шаблоны, генерация, режим спикера (дизайн — apps/web/DESIGN.md)
  cli/        oclif: клиент к api для терминала и бенчмарка
  ml/         движок: разбор .pptx, библиотека макетов, LLM-пайплайн, нативный рендер
packages/
  shared/     zod-схемы, типы, константы, типизированный клиент api
infra/
  dev/        docker-compose: postgres + redis
  prod/       docker-compose: postgres + redis + migrate + api + worker + web (nginx)
```

## Быстрый старт

Подробно, с переменными окружения, проблемами и продом: [docs/getting-started.md](docs/getting-started.md).

```bash
pnpm install
pnpm infra:up                                  # postgres :5433, redis :6380
cp -n apps/api/.env.example apps/api/.env      # заполнить LLM_BASE_URL, LLM_API_KEY, LLM_MODEL
pnpm db:migrate                                # применить миграции
pnpm dev                                       # api с воркерами на :3000, интерфейс на :5173
```

Интерфейс: http://localhost:5173, swagger: http://localhost:3000/docs

Для картинок-превью слайдов нужны LibreOffice и poppler (`brew install --cask libreoffice && brew install poppler`). Без них всё работает, а интерфейс показывает текстовое превью.

### Интерфейс

- **Презентации** — таблица с живыми статусами, блок «Идут сейчас» с этапом и таймером относительно бюджета 5 минут.
- **Новая презентация** — шаблон (по умолчанию последний), задача, длительность, материалы: папка, .zip, файлы (читаются в браузере) или git-ссылка (клонирует воркер). «Сгенерировать и начать ещё одну» сохраняет форму, чтобы запустить три генерации подряд.
- **Презентация** — режим спикера: слайд, текст спикера и тайминг рядом, плёнка миниатюр, стрелки ← → и номер слайда в адресе (`?slide=3`). Отдельный вид «Текст выступления» для репетиции, скачивание .pptx и .md, перезапуск упавшей генерации.
- **Шаблоны** — загрузка перетаскиванием, статус обучения, профиль: палитра, шрифты, тон, библиотека макетов с превью слайдов-образцов и вместимостью полей.

### CLI

```bash
pnpm cli health
pnpm cli templates upload ./brand.pptx --name "Хакатон" --wait
pnpm cli templates show <template-id>          # макеты, вместимость полей, тон бренда
pnpm cli presentations create -t <template-id> -b "Финал хакатона, аудитория — жюри" \
  -s . -s ./docs.zip -s https://github.com/org/repo -d 7 -o final.pptx
pnpm cli presentations download <presentation-id> -o final.pptx
pnpm cli bench -t <template-id> -b "Финал хакатона" -s . -d 7   # 3 параллельно, сверка с 5 минутами
```

`-s` принимает папку, `.zip`, git-ссылку (клонируется во временную папку) или файл. Зависимости, сборки, бинарники и `.env*` пропускаются. Рядом с `.pptx` сохраняется `.md` с текстом выступления.

У всех команд есть `--json` и `--api-url` (или `PM_API_URL`). Собранный бинарь `pm` лежит в `apps/cli/bin/run.js` (после `pnpm build`).

## Как работает ml

**Подготовка** (`analyzeTemplate`, время не ограничено):

1. OOXML-парсер разбирает слайды с наследованием слайд → макет → мастер → тема: координаты, кегли, маркеры, автоподгонка, группы.
2. Каждый слайд шаблона превращается в макет: роли полей (заголовок, подзаголовок, текст, карточки «заголовок + текст», колонки), вместимость каждого поля в строках и символах. Повторяющиеся на слайдах тексты (футер, логотип), номера и пустые плейсхолдеры считаются частью бренда и не заполняются. Слайды с диаграммами и таблицами пока пропускаются.
3. Палитра и шрифты — из темы и реального использования. LLM один раз описывает тон бренда по текстам шаблона.

**Генерация** (`generatePresentation`, бюджет 5 минут):

1. Выжимка материалов без LLM: README и документация первыми, потом манифесты, дерево файлов и начала исходников.
2. План (1 запрос): слайды с типом композиции, целью и фактами. Макет под каждый слайд выбирает код: тип, число пунктов, без повторов подряд.
3. Слайды параллельно (по запросу на слайд): схема ответа собирается под поля конкретного макета, лимиты символов учитывают и вместимость, и читаемость.
4. Подгонка: если текст не влез — ужать кегль до 85%, потом отдельный запрос на сокращение, в крайнем случае обрезка.
5. Нативный рендер: клонируются слайды самого шаблона, текст меняется поабзацно с сохранением форматирования, текст спикера пишется в заметки. Мастера, декор, картинки и стили остаются оригинальными.

LLM-клиент ограничивает число параллельных запросов (`LLM_MAX_CONCURRENCY`) и сам понижает режим структурированного ответа `json_schema` → `json_object` → JSON в тексте, если сервер не умеет первый. Ответ всегда проверяется zod-схемой, при ошибке — один повтор с текстом ошибки.

Замер на тестовом шаблоне (`pm bench`, 7-минутное выступление по материалам этого репозитория): **3 презентации параллельно за 15–16 с** на `openai/gpt-5.4-nano` (~12 запросов и ~22k токенов на колоду), одна колода на `deepseek/deepseek-v4-flash` через `json_object` — 52 с.

## Как устроен api

- `APP_ROLE=all` — http и воркеры в одном процессе (dev).
- `APP_ROLE=api` — только http, `APP_ROLE=worker` — только потребители очередей. В проде это один образ и два сервиса, воркеры масштабируются отдельно.
- `GENERATION_CONCURRENCY` (по умолчанию 3) — сколько генераций один воркер ведёт параллельно. Каждой задаче `@pm/ml` получает `AbortSignal` с бюджетом `GENERATION_TIME_BUDGET_MS`.
- Воркер генерации клонирует git-репозитории (`git clone --depth 1`, только https) и после сборки рендерит PNG-превью слайдов через LibreOffice. Превью шаблона строится на подготовке.
- Файлы шаблонов, результаты и превью лежат в `STORAGE_DIR` на диске, в БД хранится ключ.

## Прод

```bash
cp infra/prod/.env.example infra/prod/.env     # задать POSTGRES_PASSWORD и LLM_*
docker compose -f infra/prod/docker-compose.yml --env-file infra/prod/.env up -d --build
```

`migrate` применяет миграции из build-стейджа, затем стартуют `api`, `worker` (отдельная цель образа с git, LibreOffice и poppler) и `web` на :8080 — nginx со статикой, `/api` проксируется в api.

## Отложено

- **Замена картинок.** Картинка из слайда-образца переезжает в клон как есть, поэтому для контентных изображений (скриншоты) нужна замена или генерация.
- **Vision-анализ** шаблона на подготовке: роли свободных фигур и контентные картинки против декоративных. Сейчас роли определяются эвристиками по геометрии и кеглям.
- **Метрики шрифтов** (fontkit) вместо средней ширины символа при расчёте вместимости, шрифты бренда в контейнере рендера превью.
- **Creative-рендер** (pptxgenjs) для композиций, которых нет в шаблоне; диаграммы и таблицы.
- **Шаблоны только с макетами** (.potx без слайдов-образцов): сейчас образцом служат слайды.
- **Редактор слайдов** в интерфейсе поверх Presentation IR (сейчас просмотр, скачивание и перезапуск).
- Превью: переиспользовать профиль LibreOffice между вызовами (сейчас ~3 с на колоду из-за холодного старта), шрифты бренда в образе воркера.
- S3/MinIO вместо общего volume, линтер.
